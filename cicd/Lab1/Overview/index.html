    Lab: Building a Complete CI/CD DevOps Pipeline

    Lab Setup

    Overview

    In this lab, you will build a realistic DevOps pipeline setup used in modern applications.

    You will implement:

    • CI (Continuous Integration)
    • Integration Testing Pipeline
    • CD (Continuous Deployment)
    • Deployment using Ansible

    This lab focuses on clean architecture, not tool overload.

    End Goal

    By the end of this lab, you will:

    • Validate code automatically on every commit
    • Test your system with real dependencies (DB, Redis)
    • Build and push Docker images
    • Deploy to staging and production using Ansible

    Prerequisites

    Make sure you have:

    • [ ] Python installed
    • [ ] Docker & Docker Compose installed
    • [ ] Jenkins running
    • [ ] Git repository ready
    • [ ] Basic understanding of APIs

    Architecture Overview

    Feature Branch
   ↓
[ CI Pipeline ]
   ↓
Develop Branch
   ↓
[ Integration Pipeline ]
   ↓
Main Branch
   ↓
[ CD Pipeline ]
   ↓
Ansible → Staging → Production

    Step 1: CI Pipeline (Fast Feedback)

    Purpose

    Validate code quickly before merging.

    Trigger

    • Every push
    • Pull Requests (feature branches)

    Stages

    • Checkout code
    • Install dependencies
    • Linting
    • Unit testing
    • Static code analysis

    Example Commands

    pip install -r requirements.txt
flake8 .
pytest

    Tools Used

    • Jenkins
    • pytest
    • flake8
    • SonarQube (optional)

    Output

    • Pass / Fail only

    No Docker No Deployment

    Checklist

    • [ ] Pipeline runs on every commit
    • [ ] Execution time < 5 minutes
    • [ ] No external dependencies
    • [ ] Failing code blocks merge

    Step 2: Integration Pipeline (System Validation)

    Purpose

    Test the real system, not isolated components.

    Trigger

    • Merge into develop branch

    Stages

    1. Start Environment

    docker-compose -f docker-compose.integration.yml up -d

    2. Wait for Services

    • Ensure DB / Redis are ready

    3. Run Tests

    pytest tests/integration

    Includes:

    • API tests
    • Database tests

    4. Tear Down

    docker-compose down

    Tools Used

    • Docker
    • Docker Compose
    • Jenkins
    • pytest

    Output

    • Verified working system

    No deployment yet

    Checklist

    • [ ] Uses real services (Postgres, Redis)
    • [ ] No mocks
    • [ ] Environment reproducible
    • [ ] Clean teardown after tests

    Step 3: CD Pipeline (Build & Deploy)

    Purpose

    Package and deploy your application.

    Trigger

    • Merge into main branch

    Stages

    1. Build Docker Images

    docker build -t myapp-api .
docker build -t myapp-worker .

    2. Tag Images

    docker tag myapp-api myrepo/myapp-api:<commit-sha>

    3. Push to Registry

    docker push myrepo/myapp-api:<tag>

    4. Deploy using Ansible

    Role of Ansible

    Ansible handles:

    • Server preparation
    • Deployment execution
    • Service management

    What Ansible Does

    On staging & production:

    • Pull latest images
    • Stop old containers
    • Start new containers
    docker-compose up -d
    • Manage environment variables
    • Ensure services are healthy

    Deployment Flow

    Jenkins (CD Pipeline)
   ↓
Build Docker Image
   ↓
Push to Registry
   ↓
Run Ansible Playbook
   ↓
Deploy to Staging
   ↓
(Optional Approval)
   ↓
Deploy to Production

    Tools Used

    • Jenkins
    • Docker
    • Container Registry
    • Ansible

    Checklist

    • [ ] Images are versioned (no latest)
    • [ ] Ansible is idempotent
    • [ ] Rollback strategy exists
    • [ ] Separate staging & production

    Best Practices

    Security

    • [ ] Use SSH keys only
    • [ ] No root login
    • [ ] Secrets not stored in Git

    Options:

    • Ansible Vault
    • Environment variables

    Persistence

    • [ ] Use Docker volumes for DB
    • [ ] Backup strategy exists

    Scalability

    • [ ] Multiple containers supported
    • [ ] Reverse proxy (Nginx)

    Availability

    • [ ] Health checks configured
    • [ ] Restart policies enabled
    • [ ] Staging tested before production

    Common Mistakes

    Avoid:

    • [ ] Adding too many tools at once
    • [ ] Jumping to Kubernetes early
    • [ ] Skipping integration testing

    Focus on clean pipeline separation

    System Testing Docker
    Packaging Docker
    Deployment Ansible
    Infrastructure Terraform
