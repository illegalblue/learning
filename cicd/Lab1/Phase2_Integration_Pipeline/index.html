    Phase 2: Integration Pipeline (Jenkins + Docker)

    ← Back to Phase 1

    Goal

    Create a Jenkins pipeline that:

    • Spins up the full application stack using Docker
    • Runs integration tests against real services (Postgres, Redis)
    • Fails fast if the system is not working
    • Cleans up after execution

    Prerequisites

    • Phase 1 completed
    • Docker + docker-compose working on Dev VM
    • Jenkins installed and running
    • Project available in Git repository

    Pipeline Overview

    Git Push (develop branch)
        ↓
Jenkins Pipeline Trigger
        ↓
Spin up Docker Environment
        ↓
Health Check
        ↓
Run Integration Tests
        ↓
Tear Down Environment

    Step 1 — Jenkins Job Setup

    Create Pipeline Job

    1. Open Jenkins UI
    2. Click New Item
    3. Enter name: fastapi-integration-pipeline
    4. Select: Pipeline
    5. Click OK

    Configure Pipeline

    Under Pipeline → Definition:

    • Select: Pipeline script from SCM
    • SCM: Git
    • Repo URL: <your-repo-url>
    • Branch: develop

    Step 2 — Jenkinsfile

    Create file in project root:

    Jenkinsfile

    Jenkinsfile Content

    pipeline {
    agent any

    environment {
        COMPOSE_FILE = "docker/integration/docker-compose.yml"
    }

    stages {

        stage('Checkout') {
            steps {
                git branch: 'develop', url: '<your-repo-url>'
            }
        }

        stage('Build & Start Services') {
            steps {
                sh '''
                docker-compose -f $COMPOSE_FILE up -d --build
                '''
            }
        }

        stage('Wait for Services') {
            steps {
                sh '''
                echo "Waiting for API to be ready..."

                for i in {1..10}; do
                  if curl -s http://localhost:8000/health; then
                    echo "Service is up!"
                    exit 0
                  fi
                  echo "Retrying..."
                  sleep 5
                done

                echo "Service failed to start"
                exit 1
                '''
            }
        }

        stage('Run Integration Tests') {
            steps {
                sh '''
                docker ps
                pytest tests/integration
                '''
            }
        }
    }

    post {
        always {
            sh '''
            docker-compose -f $COMPOSE_FILE down -v
            '''
        }
    }
}

    Step 3 — Jenkins Permissions Fix

    If Jenkins cannot run Docker:

    Add Jenkins user to docker group

    sudo usermod -aG docker jenkins
sudo systemctl restart jenkins

    Verify

    sudo su - jenkins
docker ps

    Checklist

    • [ ] Jenkins can run docker commands
    • [ ] No permission denied errors
    • [ ] Pipeline executes shell commands successfully

    Step 4 — Integration Test Expectations

    Your tests should:

    • Call real API endpoints
    • Use real Postgres and Redis
    • Avoid mocks

    Example

    def test_health():
    import requests
    response = requests.get("http://localhost:8000/health")
    assert response.status_code == 200

    Checklist

    • [ ] Tests hit running container
    • [ ] No mocked DB/Redis
    • [ ] Failures break pipeline

    Step 5 — Cleanup

    Handled automatically:

    post {
    always {
        docker-compose down -v
    }
}

    Why this matters:

    • Prevents leftover containers
    • Avoids port conflicts
    • Keeps environment clean

    Common Issues

    Port already in use

    docker ps
docker stop <container>

    Services not ready

    • Increase retry count
    • Add better health checks

    Tests failing randomly

    • Likely timing issue
    • Ensure DB is ready before tests

    What You Built

    You now have:

    • A true integration pipeline
    • Real system validation (not mocks)
    • Reproducible test environment
    • Clean lifecycle (up → test → down)

    Final Checklist

    • [ ] Pipeline triggers on develop
    • [ ] Docker services start correctly
    • [ ] Health check passes
    • [ ] Integration tests execute
    • [ ] Environment is cleaned up
