    Phase 4: Hardening & Scaling (Production Readiness Basics)

    ← Back to Phase 3

    Goal

    Improve system reliability, security, and scalability:

    • Add reverse proxy (Nginx)
    • Run multiple API instances
    • Introduce basic load balancing
    • Manage secrets properly
    • Add basic monitoring & restart strategies

    Prerequisites

    • Phase 3 completed
    • Application deployed on Node1 via Ansible
    • Docker-based deployment working

    Architecture Update

                ┌──────────────┐
            │    Client    │
            └──────┬───────┘
                   ↓
             ┌──────────┐
             │  Nginx   │
             └────┬─────┘
        ┌─────────┼─────────┐
        ↓         ↓         ↓
      API-1     API-2     API-3
        ↓
      Redis
        ↓
     Postgres

    Step 1 — Update Ansible Deployment Structure

    Switch from single container → docker-compose based deployment

    Create App Directory on Node

    sudo mkdir -p /opt/fastapi-app
sudo chown -R deployer:deployer /opt/fastapi-app

    Step 2 — Create Production Docker Compose

    ansible/files/docker-compose.prod.yml

    version: "3.9"

services:

  nginx:
    image: nginx:latest
    ports:
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
    depends_on:
      - api

  api:
    image: <dockerhub-username>/fastapi-app:latest
    deploy:
      replicas: 3
    environment:
      - DATABASE_URL=postgresql://user:password@postgres:5432/appdb
      - REDIS_HOST=redis

  worker:
    image: <dockerhub-username>/fastapi-app:latest
    command: python worker/worker.py
    depends_on:
      - redis
      - postgres

  postgres:
    image: postgres:15
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: appdb

  redis:
    image: redis:7

volumes:
  pgdata:

    Note

    Docker Compose (non-swarm) does not support deploy.replicas

    Instead, scale manually:

    Step 3 — Nginx Configuration

    ansible/files/nginx.conf

    events {}

http {
    upstream fastapi_app {
        server api:8000;
    }

    server {
        listen 80;

        location / {
            proxy_pass http://fastapi_app;
        }
    }
}

    Step 4 — Update Ansible Playbook

    ansible/deploy.yml

    - name: Deploy Application (Production Style)
  hosts: node1
  become: yes

  vars:
    app_dir: /opt/fastapi-app

  tasks:

    - name: Create app directory
      file:
        path: "{{ app_dir }}"
        state: directory

    - name: Copy docker-compose file
      copy:
        src: files/docker-compose.prod.yml
        dest: "{{ app_dir }}/docker-compose.yml"

    - name: Copy nginx config
      copy:
        src: files/nginx.conf
        dest: "{{ app_dir }}/nginx.conf"

    - name: Pull latest images
      command: docker-compose pull
      args:
        chdir: "{{ app_dir }}"

    - name: Start services
      command: docker-compose up -d
      args:
        chdir: "{{ app_dir }}"

    Step 5 — Scale API Containers

    Run on Node1:

    cd /opt/fastapi-app
docker-compose up -d --scale api=3

    Verify:

    docker ps

    Checklist

    • [ ] Multiple API containers running
    • [ ] Nginx running on port 80
    • [ ] Requests routed via Nginx

    Step 6 — Health Check Endpoint

    Ensure your FastAPI app has:

    @app.get("/health")
def health():
    return {"status": "ok"}

    Test:

    curl http://<NODE1_IP>/health

    Step 7 — Restart Policy

    Update compose:

    restart: always

    Apply to:

    • api
    • worker
    • postgres
    • redis
    • nginx

    Checklist

    • [ ] Containers restart automatically
    • [ ] System recovers after reboot

    Step 8 — Secrets Management (Basic)

    Move credentials to .env

    ansible/files/.env

    POSTGRES_USER=user
POSTGRES_PASSWORD=password
POSTGRES_DB=appdb

    Update compose:

    env_file:
  - .env

    Update Ansible:

    - name: Copy env file
  copy:
    src: files/.env
    dest: "{{ app_dir }}/.env"

    Checklist

    • [ ] No secrets in compose file
    • [ ] Env file used
    • [ ] Ready for Ansible Vault

    Step 9 — Basic Logging

    View logs:

    docker-compose logs -f

    Optional:

    • Redirect logs to files
    • Rotate logs (future improvement)

    Step 10 — Basic Monitoring (Minimal)

    Install on Node1:

    docker run -d -p 9100:9100 prom/node-exporter

    Verify:

    curl http://<NODE1_IP>:9100/metrics

    Common Issues

    Containers not balancing

    • Nginx config incorrect

    API not reachable

    • Port mismatch
    • Container not running

    DB connection errors

    • Wrong env variables
    • Postgres not ready

    What You Built

    You now have:

    • Reverse proxy (Nginx)
    • Multiple API instances
    • Load balancing
    • Persistent database
    • Basic secrets handling
    • Restart resilience

    Final Checklist

    • [ ] Nginx routing traffic
    • [ ] Multiple API containers running
    • [ ] Database persistent
    • [ ] Secrets externalized
    • [ ] Containers auto-restart
    • [ ] Basic monitoring enabled
